## 正規化內容筆記（AI 生成改寫）

### RAG 四步驟

1. **建立索引**：清理、格式化並切分文件，為文件建立 embedding，然後存入 vector database。AWS 將此描述為前期、通常只需執行一次的活動。
2. **提出 Query**：使用者以自然語言提出問題。
3. **Retrieval 與 Context Augmentation**：orchestrator 透過相似度搜尋取得相關資料，再把這些內容作為 context 加到包含 query 的 prompt。
4. **Generation**：orchestrator 把 query 與 context 送入 LLM，模型利用額外 context 產生回答。

原文定位：主標題下的四個編號步驟。  
來源：https://docs.aws.amazon.com/prescriptive-guidance/latest/retrieval-augmented-generation-options/what-is-rag.html

### Production-level components

- **Connectors**：連接企業資料來源與 vector database。
- **Data processing**：從 PDF、掃描影像、文件、簡報等格式擷取並準備可索引內容。
- **Embeddings**：把文件與查詢轉為可用於相關性搜尋的數值表示。
- **Vector database**：保存 embedding、對應文字與 metadata，並針對搜尋與檢索最佳化。
- **Retriever**：依 query 取得相關 context，並按照需求排序結果。
- **Foundation model**：通常是 LLM，根據 context 與 prompt 產生並格式化回答。
- **Guardrails**：用來約束 query、prompt、retrieved context 與 response 的準確性、責任性、倫理及偏誤等風險。
- **Orchestrator**：排程並管理端到端流程。
- **User experience**：提供使用者互動介面、對話歷史或回饋能力。
- **Identity and user management**：控制使用者存取權限。

原文定位：Components of production-level RAG systems。  
來源：https://docs.aws.amazon.com/prescriptive-guidance/latest/retrieval-augmented-generation-options/what-is-rag.html
