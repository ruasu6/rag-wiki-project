## 正規化內容筆記（AI 生成改寫）

### 定義與目的

Chunking 是把較大的文字內容分成較小單位。它能讓輸入維持在 chat completion 或 embedding model 的限制內，避免內容因截斷而遺失；即使文件沒有超過限制，如果整份文件涵蓋多個主題、難以由單一向量良好表示，較細的切分仍可能更合適。

原文定位：主標題下的導言；Common chunking techniques。  
來源：https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-chunk-documents

### 常見策略

- **Fixed-size**：用固定的字數、字元數或 token 數切分。規則簡單，但大小仍要足以承載有意義的段落，並可搭配少量 overlap。
- **Structure-based／variable-sized**：依句尾、換行或文件結構切分；HTML／Markdown 標題也可作為段落邊界。此名稱是對原文 `Variable-sized chunks based on content characteristics` 的教學整理。
- **Semantic**：依語意關係形成有意義的單位，目標是保留跨句子與段落的連貫性；chunk 大小可以不固定。
- **Custom combinations**：可組合固定與變動長度策略，或在 chunk 中補入文件標題等資訊以降低上下文流失。
- **Document parsing**：可把來源解析成較小的搜尋文件；原文明確指出這嚴格來說不一定是 chunking，但有時達到相近目的。

原文定位：Common chunking techniques。  
來源：https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-chunk-documents#common-chunking-techniques

### Overlap 與大小選擇

固定長度切分時，讓相鄰 chunk 重複少量文字可以維持上下文連續性。Microsoft 文件提供 512 tokens、25% overlap 作為起始建議，但同時指出最佳 overlap 會依內容與使用情境改變，因此它不是所有系統的固定答案。文件結構與密度、預期查詢，以及所有下游模型的輸入／效能限制，都是 chunk size 的考量因素。

原文定位：Content overlap considerations；Factors for chunking data。  
來源：https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-chunk-documents#content-overlap-considerations

### 在流程中的位置

大型文件可在 indexing 與 query workflow 中加入切分步驟。常見的資料準備順序是先把文件切成 chunk，再為 chunk 建立 embedding 與索引；實際工具可以是受管服務、custom skill 或外部函式庫。文件也說明多數函式庫支援固定、變動長度或組合策略，並能設定 overlap。

原文定位：How chunking fits into the workflow。  
來源：https://learn.microsoft.com/en-us/azure/search/vector-search-how-to-chunk-documents#how-chunking-fits-into-the-workflow

## 通用原理與 Azure 特定功能的界線

### 可作為通用 Chunking 原理

- 依固定長度、內容結構、語意或組合策略切分。
- 使用少量 overlap 維持相鄰 chunk 的上下文。
- 依文件、查詢與模型限制調整 chunk size。
- 把 chunking 放在 embedding／索引之前的資料準備流程。

### 僅作為 Azure AI Search 實作例子

- Azure AI Search indexers、skillsets 與 integrated vectorization。
- Text Split skill、Azure Content Understanding skill、custom skill。
- `textSplitMode`、`maximumPageLength`、`pageOverlapLength`、`maximumPagesToTake` 等產品參數。
- Azure portal、REST API、SDK 與 Foundry IQ。

以上 Azure 功能不得泛化為所有 RAG 系統的必要元件。
